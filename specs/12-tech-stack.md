## 1. עקרונות

1. **שירותים מנוהלים של AWS** לכל מה שאינו הליבה. הצוות מכיר AWS, ומשתמש אחד לכל מפעל לא מצדיק לבנות תשתית בעצמנו.
2. **מעט רכיבים בגרסה 1.0.** כל רכיב נוסף הוא עוד דבר שצריך לנטר ולשדרג.
3. **רישיון כל ספרייה נבדק לפני השימוש.** במוצר SaaS סגור, ספרייה ב-AGPL מחייבת רישיון מסחרי או החלפה (סעיף 8).
4. **הליבה ב-Python**, כולל העיבוד, הצינור וה-API. אין שירות בשפה אחרת בגרסה 1.0.

## 2. תמונה כללית

```

   │  HTTPS

   ▼

              ▼

              │

```

## 3. צד השרת

| שכבה | בחירה | למה |
| --- | --- | --- |
| שפה | Python 3.12 | החלטה קיימת. כל הספריות של העיבוד ב-Python |
| API | **FastAPI** + **Pydantic v2** | החוזים בין השלבים הם מודלי Pydantic (`konboro_llm` כבר עובד כך) |
| גישה למסד | SQLAlchemy 2 + Alembic | כל שינוי מבנה הוא migration |
| מסד נתונים | **Amazon RDS for PostgreSQL** | Row Level Security להפרדת מפעלים ([00 §8](00-architecture.md)), `numeric` לכסף |
| חיפוש דמיון | **pgvector** באותו מסד | אינדקס הסימנים ([03](03-symbol-detection.md)) בלי שירות וקטורים נפרד. בהיקף של גרסה 1.0 זה מספיק |
| תור | **Amazon SQS**, תור לכל שלב + תור כישלונות (DLQ) | מנוהל, בלי Redis. ניסיון חוזר לכל שלב בנפרד, וכישלון לא מאבד עבודה |
| קבצים | **Amazon S3**, תיקייה לכל מפעל, הצפנה עם KMS | שרטוטים, עמודים מרונדרים, אריחים, גרף חיבורים |
| כסף | `Decimal` בקוד, `numeric` במסד | אף פעם לא float ([07](07-pricing.md)) |
| קבצי אקסל | openpyxl, pandas | מסלול כתב הכמויות ([01 §5.8](01-intake-page-classification.md)) |
| PDF ללקוח | HTML שמודפס דרך Chromium (Playwright) | הכי אמין לעברית ולשילוב של עברית ומספרים |

**הצינור:** כל שלב הוא worker שקורא מתור ה-SQS שלו, כותב את הפלט לפי החוזה ([00 §5](00-architecture.md)), ושולח הודעה לתור של השלב הבא. הקורדינטור הוא קוד, כמו בארכיטקטורה. ההודעות מכילות מזהים בלבד, והנתונים עצמם ב-RDS וב-S3.

## 4. מודלים: Claude דרך Amazon Bedrock

| נושא | החלטה |
| --- | --- |
| גישה | **Amazon Bedrock**, דרך `AnthropicProvider.for_bedrock()` במודול `konboro_llm` |
| למה Bedrock ולא ה-API של Anthropic ישירות | הרשאות IAM במקום מפתח API, חשבונית אחת ב-AWS, וניטור ב-CloudWatch |
| נקודת קצה | **גלובלית.** בלי תוספת מחיר, וזמינות גבוהה. נקודת קצה אזורית עולה 10% יותר, ומיועדת לדרישות שהנתונים יישארו באזור, שאין לנו |
| מודלים | Haiku, Sonnet ו-Opus 5.5, לפי מפת המודלים ([00 §7.1](00-architecture.md)). ב-`config.py` השמות כלליים ("claude-sonnet-5-5"), והספק מוסיף את הקידומת של Bedrock ("anthropic.") |
| לבדוק לפני היום הראשון | גישה למודלים בחשבון (חלקם דורשים הפעלה בקונסולה), ומכסות (טוקנים לדקה) |

**המעבר ל-API הישיר של Anthropic, אם יידרש, הוא שורה אחת:** `AnthropicProvider()` במקום `AnthropicProvider.for_bedrock()`. קוד השלבים לא משתנה.

## 5. עיבוד שרטוטים

| שכבה | בחירה | הערה |
| --- | --- | --- |
| רינדור PDF | **pypdfium2** (Apache 2.0 / BSD) | במקום PyMuPDF (סעיף 8) |
| קווים, מלבנים, שכבת טקסט | **pdfplumber** (MIT) | חילוץ וקטורי ([02 §2.2](02-extraction-tiling.md)) |
| עיבוד תמונה | OpenCV, Pillow | |
| OCR | **השוואה על סט הבדיקה**: Google Cloud Vision מול Azure AI Document Intelligence | ראו למטה |
| גלאי סימנים (שלב 3 ייעודי, אחרי גרסה 1.0) | RT-DETR דרך Hugging Face, או Detectron2 (שניהם Apache 2.0) | **לא YOLO של Ultralytics** (AGPL). אימון על Amazon SageMaker, ושרת GPU רק כשמגיעים לשם. עד אז: LLM ראייה דרך `konboro_llm` ([03 §3.2א](03-symbol-detection.md)) |

**OCR היא ההחלטה הטכנית החשובה ביותר בגרסה 1.0.** בכל חמשת השרטוטים בסט כל הטקסט הוא קווים, ולכן כל הפענוח עובר דרך OCR ([02 §2.3](02-extraction-tiling.md)).

- **Amazon Textract לא מועמד.** הוא לא תומך בעברית: השפות שלו הן אנגלית, ספרדית, גרמנית, איטלקית, פורטוגזית וצרפתית.
- **המועמדים** מחוץ ל-AWS, דרך API: Google Cloud Vision ו-Azure AI Document Intelligence. שניהם מחזירים מיקום לכל מילה, ותומכים בעברית ובטקסט מסובב.
- **ההשוואה:** על 5 השרטוטים בסט, לפי דיוק אסימונים חשמליים ("C16", "3X25A", "INC=8A") ועברית קטנה ואנכית ([02 §10](02-extraction-tiling.md)), ולא לפי דיוק כללי.
- **תנאי הספק:** בלי אימון על הנתונים ובלי שמירה ארוכה ([00 §7.3](00-architecture.md)). לבדוק את תנאי ה-API של המנצח לפני השימוש.
- **עד ההשוואה (S10):** מנוע זמני, Claude דרך `ocr_transcription`, מאחורי הממשק `OcrEngine`, עם בדיקות קוד על כל תשובה ([02 §2.3](02-extraction-tiling.md)). המנצח בהשוואה (S31) נכנס כמימוש נוסף של אותו ממשק.

## 7. תשתית ותפעול

| נושא | בחירה |
| --- | --- |
| אזור | **eu-central-1 (פרנקפורט).** כל השירותים זמינים בו, וזמן התגובה מישראל מספיק למערכת שהעבודה הכבדה בה רצה ברקע. אפשר לשקול את il-central-1 (תל אביב) בהמשך, אחרי בדיקה שכל השירותים שבסעיף 2 זמינים שם |
| הרצה | **ECS Fargate.** שירות API ושירות workers נפרדים, כי רינדור ו-OCR כבדים. ה-workers גדלים לפי אורך התור |
| הזדהות | **Amazon Cognito**, עם `tenant_id` בטוקן. משתמש אחד לכל מפעל ([00 §14.1](00-architecture.md)) |
| סודות | AWS Secrets Manager. מפתחות ה-OCR שם. Bedrock לא צריך מפתח, רק תפקיד IAM |
| תשתית כקוד | Terraform (או AWS CDK, לפי מה שהצוות מכיר) |
| CI/CD | GitHub Actions: בדיקות, **הרצה על סט הבדיקה בכל שינוי בצינור**, בנייה, ופריסה ל-ECS |
| שגיאות | Sentry |
| לוגים ומעקב | CloudWatch, ו-OpenTelemetry לכל שרטוט לאורך כל השלבים (`trace_id` מ-[01](01-intake-page-classification.md)) |
| עלות לכל מפעל | טבלה מהרישום של `konboro_llm` ועלות ה-OCR לכל עמוד. העלות של עמוד גדול תלויה בשטח שלו ([01 §4.3](01-intake-page-classification.md)) |
| גיבויים | גיבוי אוטומטי של RDS, וגרסאות ב-S3 |
| דגלי תכונות | טבלאות במסד, עם מטמון בשרת. AWS AppConfig אם יידרש rollout באחוזים ([13](13-feature-flags.md)) |
| קול | Amazon Transcribe, שתומך בעברית (`he-IL`). נרמול מונחים אחרי התמלול ב-LLM ([13 §4.2](13-feature-flags.md)) |

## 9. נקודות פתוחות

1. **מנוע ה-OCR:** תוצאות ההשוואה על סט הבדיקה (סעיף 5).
2. **Terraform או CDK:** לפי מה שהצוות מכיר.
3. **אזור:** פרנקפורט כברירת מחדל. לשקול תל אביב אחרי בדיקת זמינות השירותים.
4. **מכסות Bedrock:** להעריך טוקנים לדקה לפי שרטוט טיפוסי, ולבקש הגדלה לפני הפיילוט.
5. **מודל ה-embedding** לאינדקס הסימנים: לבחור ולבדוק רישיון.
