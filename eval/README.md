# Golden-set evaluation

`make eval` runs the pipeline on every drawing in `golden/`, scores each stage against the labels, writes a report, and compares it with `baseline.json`. The method is in [dev-strategy.md §6](../docs/dev-strategy.md#6-golden-evaluation). The decisions are in [S06](../docs/sessions/S06-golden-eval.md).

## Running it

| Command | What it does |
| --- | --- |
| `make eval` | Replay mode: the model's answers come from `cassettes/`. Deterministic and free. CI runs it |
| `EVAL_MODE=live make eval` | Real Claude. `ANTHROPIC_API_KEY` must be exported in the shell: the eval does not read `.env` (S17) |
| `EVAL_MODE=live EVAL_RECORD=1 make eval` | Real Claude, saving every answer as a cassette. Commit the new cassettes |
| `EVAL_MODE=live EVAL_RECORD=missing make eval` | Replays what is recorded and sends only the calls with no cassette to Claude, saving them. For a new stage or prompt, so the stages before it keep their recorded answers |
| `EVAL_MAX_USD=20` (with `EVAL_MODE=live`) | Stops the run once its calls cost this much at list prices. The call that crosses the line finishes; the next one fails the run |
| `EVAL_CATALOG_LINES=1 make eval` | The eval factory and the backtest with `catalog_lines` on (S27b; 13 §3 rule 6, both states of a flag that moves the pipeline). Reported against the baseline, which is the flag off |
| `make eval-baseline` | Make this run's metrics the new `baseline.json`, after a change that moves a score on purpose |

Every run needs `make up`. Two runs cannot overlap, `make check`'s included: each recreates the `konboro_eval` database, uploads each drawing to one throwaway tenant, and runs the 7 stages in-process, without the queue (`Pipeline.run_inline`).

A missing cassette fails the run with "no cassette for stage …". This happens when a prompt, a schema, an input or a model changed. To fix it, record again in live mode.

The tile agent (`text_association`, stage 4) and `validator_review` (stage 6) are the exceptions: a missing cassette makes them fall back to code's reading without an error, so a miss shows only as a lower `agent_instances` or `cited_values`. **Replay can differ by platform.** pdfium can render a page a few pixels differently on macOS and on CI's Linux amd64; stage 3's ink-shrunk boxes then move a pixel, and a tile's prompt with them (BUG-073, on 25.26.100). When CI's numbers differ from a local replay, replay the drawing in a `linux/amd64` `python:3.12-slim` container, compare the missed requests with the local ones, and when a box's pixel is the only difference, store the recorded answer under the Linux key as well.

## Layout

| Path | What |
| --- | --- |
| `canonical.py` | One shape for every label file and for the pipeline's output |
| `normalizers/` | One normalizer per label shape. The shape is recognised from the file's keys. Known quirks (`single_line`, missing routes, designator ranges) are mapped in `common.py` |
| `predict.py` | Stage contracts → the canonical shape |
| `metrics/` | Stage 1 (01 §10), stages 2–3 (S10, S12), stage 4 (04 §10), stage 5 (05 §10, S20), audit (11 §10), pricing backtest (07 §10.2) |
| `labelled.py` | Stage 5 on components built from the labels (05 §10) |
| `validation.py` | Stage 6's findings, its rules on the labelled quote, and the injected-error set (06 §10.1, S21) |
| `report.py`, `compare.py` | The JSON and markdown report, and the comparison with the baseline |
| `cassettes/<stage>/<hash>.json` | Recorded model answers (`konboro_llm.providers.CassetteProvider`) |
| `reports/` | `<timestamp>.json` and `.md` (git-ignored) |

## Reading the scores

- **`n/a`** means there was nothing to score: no label for it, or nothing produced yet. It is never 0%.
- **Stage 2** is scored by `designator_recall`: the labelled designators found among the normalized text of the `process` pages (S10).
- **Stage 3** (S12) has no symbol-box labels, so precision isn't measured. On factory drawings, `designator_recall` is the share of labelled designators that some detection carries, and `family_accuracy` the share of those found with the label's family (any role). On a designer's plan without designators, `family_count_recall` compares detections per family with the label's rows. `s3_family` gives recall per family (03 §10). `duplicates_left` (03 §10: 0) and `llm_share`, the share of detections sent to the disambiguation call (03 §10: at most 10%), are "lower is better". The stage's counts (accepted, uncertain, unknown, orphan texts, calls) are in the report's "Stage 3 counts".
- **Stage 4 matching.** On factory drawings, components match by family + designators. With no designators (designer plans, BOM-only), they match by family + `current_a` + poles, with quantities added up. So merged and unmerged rows score the same. `current_a` and poles accuracy are measured on designator matches only.
- **Stage 4 is scored end to end** (S13): on stage 3's output, since no label has symbol boxes to feed it (04 §10). The report adds stage 4's counts per drawing: tiles sent to the tile agent, agent calls, values cited and `citation_mismatch`es, instances, components and missing instances, and the values written without evidence, which must be 0.
- **Stage 5** (S20). No label holds a SKU, so top-1 and top-3 accuracy are not measured (S20 decision 2). End to end (`s5`), on stage 4's pairs with the labels: `sku_value_accuracy` (the chosen item has the labelled current and poles; a miss may be stage 4's reading), `with_sku`, `consistency` (one SKU per signature in a drawing, 05 §10: 100%) and `llm_share` (signatures the agent decided, at most 15%, lower is better). On the labelled attributes (`s5_labelled`, stage 5 alone, `labelled.py`): `exact_value_accuracy` (05 §10: no wrong value), `unmatched_in_catalog` (labelled components the catalog has an item for that came out `unmatched`, at most 1%, lower is better; a `conflict` like FNV's is right and not counted), `consistency` and `llm_share`. The eval's tenant is a factory that quotes ABB, allows Schneider, and fills a breaker's curve C and 6 kA (`run.FACTORY`); it has no price list, so every brand counts as priced. The report adds stage 5's counts per drawing (`matching`).
- **Stage 6** (S21). End to end (`s6`): `golden_findings`, the findings the golden drawings call for (`metrics/stage6.EXPECTED`, from the labels' notes and 06 §6.2's examples; the golden files are not changed), and `errors` and `warnings` per drawing (lower is better), to watch the noise. On the labelled quote (`s6_labelled`, rules only, `validation.py`), which is correct by definition: `false_errors` and `false_warnings` per drawing (06 §10.2: at most 0.1 and 3), `bug_net_fired` (category D's safety nets, 0), and `injected_caught`, the share of injected errors a new warning or error points at (06 §10.2: at least 95%), with `injected_<kind>` per kind. An injected error counts only where a rule can see it (a front view or a designer's BOM for a quantity or a deleted component, a main device for a current); `injected_not_applicable` counts the rest. The labelled quote has no wire graph and no text spans, so the hierarchy and coverage rules are measured only end to end. The eval's factory has no price list and turns `DATA_NO_COST_PRICE` off. The report lists each drawing's findings and injected errors.
- **The audit** (S15, 11 §10) runs on every drawing with a real quote (`actual_quote_*.pdf`: NEVIS-1, 26-993, NURSERY-1, 25.26.100), on the run's own stage 1 and 4 outputs, with the same code as the audit step. The quote's page goes through `table_transcription` (its cassette). `difference_precision` counts the shown differences (confidence ≥ 0.6) that share a designator with a confirmed one; `difference_recall` the confirmed ones that some shown difference shares a designator with. A confirmed difference with no designator (25.26.100's untagged breakers) is matched by the quote lines it names (`quote_lines`), and an omission with no line by its `family`. The match is not one to one: a confirmed difference split by component is found, and both parts are right. `type_agreement` compares the types, a short, an over and a double count all being `quantity_mismatch`.
- **Backtest** (07 §10.2, S22, `backtest.py`). Each drawing with a real quote is priced again by stage 7's pure engine on the run's own stage 1–6 outputs. Gated: priced from its own quote's prices, by the audit's line-to-component matches (each matched SKU gets its line's unit price as a fixed price; the cabinet line prices the enclosure), so `backtest_within_5pct` / `backtest_deviation` measure our quantities, derived items and rounding against the total before VAT, and `backtest_derived_within_10pct` / `backtest_derived_deviation` our derived items against the quote's cabinet lines. Reported, not gated: leave one out, priced from the other quotes, with the share of component lines that found a price. The eval factory follows these quotes' factory: the cabinet includes busbars, N, PE, panels and doors, and only the enclosure rule runs. The real quotes left out items the factory confirmed, so the report shows the confirmed value at risk next to each total, and the audit's own (`predicted_value_at_risk`).
- **The chat** (S25, 08 §13, `chat.py`, `chat_set.json`). About 60 Hebrew requests, each one turn of a new conversation on the NURSERY-1 fixture, in a factory with the demo price list, with a text that gives orders planted beside Q0 on the drawing. The coordinator's calls replay from `cassettes/chat_command/`. `tool_accuracy` (the expected tools with the expected arguments, a subset match; 08 §13.2: ≥ 95%), `clarification_accuracy` (a question when the request needs one, and only then; ≥ 90%), and, lower is better and all 0 by 08 §13.2: `forbidden_calls`, `injection_followed`, `money_to_model` (model calls whose text had an amount from the quote), `invalid_refs`, `amounts_removed`. The report lists the requests that missed. A prompt or tool-schema change misses every cassette: record with `EVAL_MODE=live EVAL_RECORD=missing`.
- **Overall** (S28, 00 §10.2, phase 2's exit, `metrics/rows.py`). `rows_without_edit`: the labelled rows (one component of a checked panel, in the panel, terminals left out as the factory's auxiliary material) for which the pipeline's quote has a line with the label's family, quantity and every labelled value its family's schema has (from the chosen catalog item, else from stage 4's reading), and a SKU from stage 5 (no SKU, no price: an edit). Rows with no designators are scored as a group by family, current and poles. Phase 2's target is 85%, phase 3's 95%. `wrong_green_rows` (≤ 1%, lower is better): of the component lines green apart from their price, the share that need an edit or pair with no label. Apart from the price because the eval's factory has no price list, so every line's price reason is red; n/a means no line was green.
- **Regressions.** A metric that is lower than the baseline, or that had a value and now is n/a, fails `make eval` and the CI job. For "lower is better" metrics (`missed_process_pages`, `backtest_deviation`, `backtest_derived_deviation`, `confirmation_rate`, `duplicates_left`, `llm_share`), a higher value fails.

- **The chat builder and the chat home** (S27, 13 §4.2–4.3, `build.py`, `build_set.json`, `home_set.json`). The builder's cases are typed, spoken (numbers in words, as Transcribe writes them) and multi-turn messages, each case a new build in a factory with the demo price list, through `services.build.message`, so `chat_bom_extraction` and stage 5's `catalog_disambiguation` replay from their cassettes. After each turn the draft's components are compared with the expected ones (family, the values given, quantity). `build_line_accuracy`, `build_turn_accuracy` (the whole draft exactly), `build_clarification_accuracy`, and, lower is better: `build_invented_values` (a value no message of the case said), `build_dropped` (the code check's catches), `build_money_to_model`. The home's requests are routed by `services.home_route.route` in a factory with three quotes: `home_route_accuracy` and `home_money_to_model` (an amount, a quote's name or a customer in a model request). The report lists the turns and requests that missed.

## Adding a drawing

Put it in `golden/<id>/` with a `README.md`, `labels.json` and, if there is one, `actual_quote.json`. A panel the user has not checked yet goes in with `verified: false` and no components (25.26.100's sub-panel): stage 1 counts it as a panel, stage 4 does not score it. If the labels use a known shape, nothing else is needed. Otherwise add a normalizer to `normalizers/shapes.py` and a case to `normalizer_for`. Then run `make eval-baseline` and commit the new baseline with the drawing.
